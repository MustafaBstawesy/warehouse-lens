# Demo Script

Goal: a 45-60 second screen recording of the full happy path - scan a material,
find stock at another warehouse, submit a transfer request, and see it tracked.
Everything shown is real, persisted behavior of the CAP backend; nothing in the
main script is mocked on screen.

Honest framing for anything you publish alongside the recording: the app
**submits a transfer request for approval - stock is not moved**, nothing is
reserved or decremented, and there is no S/4HANA goods movement in this MVP.

## One-time preparation

1. Reset and seed the demo database (from `cap/`):

   ```bash
   npm run demo:reset
   ```

   This deletes `cap/db.sqlite` and reseeds master data plus a small set of
   demo requests with realistic timestamps. A guard script refuses to run
   against anything that looks like a cloud or production environment.

2. Start the backend (from `cap/`):

   ```bash
   npm run watch
   ```

3. Make the backend reachable from the device. A phone cannot reach the dev
   machine's `localhost`; use the machine's LAN IP as described in
   `docs/local-development.md` (mocked-auth basic credentials: user `alex`).

4. Prepare the QR label. Either print `assets/qr-labels/print-sheet.html`
   (all demo labels on one page) or open `assets/qr-labels/MAT-1042.png` on a
   second screen and scan it from there.

5. Do one full rehearsal run, then reset again before recording.

## Click-by-click script

Times are targets for a 55-60 second cut. The greeting follows the time of
day ("Good morning" before noon), so record in the morning if you want the
line below verbatim.

| Time | Screen | Action |
| ---- | ------ | ------ |
| 0:00 | Home | Show "Good morning, Alex" with home warehouse Cairo, pending requests 1, low stock 4. Pause one beat. |
| 0:08 | Home | Tap **Scan material**. Scan the printed MAT-1042 QR label with the camera. Fallback if scanning is awkward on camera: tap **Use demo material MAT-1042**. |
| 0:20 | Material details | Precision bearing, MAT-1042, **0 EA available at Cairo**. Tap **Find stock**. |
| 0:30 | Find stock | Alexandria is at the top with **240 EA available**. Tap the Alexandria row to select it, then tap **Select Alexandria**. |
| 0:38 | Review | Quantity stepper shows **20 EA**, optional note field with live character counter, and the approval hint text. Tap **Submit request**. |
| 0:48 | Confirmation | Real transfer request reference (for example TR-001006) with the timeline: Submitted done, Awaiting approval current, Dispatch and Received pending. |
| 0:55 | Requests | Tap **View requests**, then set the status filter to **Awaiting approval**. The new request is in the list. End recording. |

Note: the reference number is generated by the backend counter, so it
increments across takes. Reset between takes (below) to keep it stable.

## What to say over each step

Keep each line short and honest:

- 0:00 - "Warehouse Lens. Alex works at the Cairo warehouse - one pending request, four materials running low."
- 0:08 - "Scan a material's QR label with the device camera."
- 0:20 - "Precision bearing - zero on hand at Cairo. Let's find stock elsewhere."
- 0:30 - "Alexandria has 240 available - ranked first. Select it as the source."
- 0:38 - "Review: 20 units, an optional note, and a reminder that this goes to approval. Submit."
- 0:48 - "The backend validates and persists it, and returns a real reference with a status timeline. This submits a transfer request for approval - stock is not moved."
- 0:55 - "Every request is tracked and filterable - here, everything awaiting approval."

## Resetting between takes

From `cap/`:

```bash
npm run demo:reset
```

Then force-close and relaunch the app on the device so the Home counters and
request list reload fresh (the client caches page state within a session).
After a reset, the first new submission gets the same reference again
(TR-001006), which keeps takes consistent.

## Optional: simulated status progression (dev-only)

If you want a second, clearly separated clip showing the timeline advancing,
the backend ships a **simulated** progression script. It is a local demo aid
only - there is no approval workflow or ERP integration behind it, and every
event it writes is labeled `[SIMULATED]`.

```bash
npm run demo:advance TR-001006
npm run demo:advance TR-001006 -- --reject "Stock needed locally"
```

Each call moves the request one status forward (or rejects it). Pull down or
reopen the request detail page to see the updated timeline. If you show this
on camera, say so: "status changes here are simulated locally for the demo."
